Kubernetes and an agent

The agent lives in the cluster. It can see what is running. It cannot change it except by a pull request I merge.

That is the whole idea.

The other three

Full access. The agent holds a credential that can change the cluster and can merge. The author and the reviewer are the same actor. A wrong turn is already live. A review rule does not hold, because the account that opened the change is the account that can approve it.

No access. The agent can talk and cannot see. Every claim about the cluster is a guess. I become a copy-paste proxy. The agent never checks its own advice against the thing it is advising on.

A laptop. The model runs on a machine that leaves the house. The session ends when the lid closes. The credential is mine, so the cluster cannot tell the agent's commits from mine. Nothing about that setup survives the laptop.

This one

It can read the live cluster, so it argues from the cluster, not from memory. Workloads, logs, events, network policy, and whether a release is healthy. The role is read only. It cannot create, update, or delete.

It cannot apply a change. The change is a diff. Git is what the cluster applies.

It is not my account, so it cannot approve that diff. I can merge my own pull request, because there is no second person. The agent cannot.

The key that mints its identity is not in the container the model drives. That container gets a token that expires.

It cannot edit the checks that gate it. It reaches the API because a policy says so. The network denies traffic unless a policy allows it.

A dependency bot can merge a version bump after checks pass. That bot is not the agent. The gate is the split between the agent and me, not a second employee. A tired review can still merge a wrong diff.
