Kyverno: admission policies watching the agent

Two ClusterPolicies enforce the agent's identity — one keeps it read-only, the other refuses privileged calls even if RBAC is widened.

Admission policies: three layers, different blind spots

Three layers, and they see different things. The layering only works if each one is genuinely blind to what the others cover.

Admission

Kyverno sees intent: what a manifest asks for, before it exists. Holds the two agent-identity policies.

Scanning

Trivy Operator sees images: reports high/critical findings with a fix available.

Runtime detection

Sees behaviour: what a process does after it starts. Falco with a curated rule set — the layer that catches what the other two can't.

The layering only works if each one is genuinely blind to what the others cover. That is the argument for running all three: they fail differently, and together they cover intent, contents, and behaviour.

Falco: runtime syscall detection

What a process does after it starts — which admission and image scanning structurally cannot see.

Falco runs with a curated rule set rather than the whole upstream one. It's the layer that generates the most noise, so the exemptions are written narrow on purpose — by process, parent and host, never by file path or image name.

Narrow exemptions

When a legitimate process trips a detection rule, the exemption is scoped to that process, its parent, and the host. Never to a file path, and never to an image name — a generic base image is a whole class of containers, and a path is exactly what the attacker touches.

Fail-open trade-off: The policy that refuses pod exec, token minting and Secret writes made as the agent doesn't run if Kyverno is down. Failing closed there would block every Secret write in the cluster, so it's a trade: what it covers, its RBAC already covers too.
