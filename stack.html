The stack

What each piece is for, and why that one

Nothing here was picked because it was popular. Each entry answers a question I actually had, and where the honest answer is "this is what I'd do differently", that's the entry.

Running the cluster

ToolWhy this one
MicroK8sInstalled from a snap, so the OS and its upgrades are one mechanism and a node is rebuildable from a playbook.
Flux CDThe only thing that writes to the cluster. Continuous reconcile means anything not in a merged commit gets reverted — which is what makes "the agent can try things" a bounded risk.
Flux OperatorDeclares the Flux install as an object in git, so there's no hand-run bootstrap nobody can reproduce.
DexSSO for humans, not workloads. The API server trusts it as an OIDC issuer, so access is a token with an expiry rather than a cert copied between machines.
Kustomize + HelmHow a directory becomes YAML: overlays and pinned chart values, so two environments differ by a small diff.

Traffic in, certificates out

ToolWhy this one
TraefikRouting, TLS and middleware in one CRD instead of three annotations, and one wildcard cert serves every route.
MetalLBReal LAN addresses for LoadBalancer services, so ingress behaves like ingress instead of a router port-forward.
cert-managerRenewal is somebody else's job, because an expired cert looks exactly like an outage.
external-dnsPublishes the record from the object that declares the route. One manual step gone per hostname.

Storage and secrets

ToolWhy this one
LonghornReplicated block storage with no SAN to buy. The heaviest thing here and still worth it: a node can die without taking a volume. Upgrades wait for an explicit window.
1Password Connect + External Secrets OperatorThe only path a secret value takes to a pod. Nothing in git, and the agent has no read path at all.
Stakater ReloaderRestarts a workload when its secret changes. Without it the Secret is rewritten and the pod never notices — a bug that survives for months because nothing is wrong.

Keeping the agent honest

ToolWhy this one
KyvernoAdmission policies, including two on the agent's own identity. It refuses rather than reports, and the CI fixtures must refuse.
NetworkPolicyDefault-deny both ways in every namespace. Also the most common cause of a connectivity bug I'll chase — diagnosable because the answer is a file, not a guess about the prompt.

Noticing problems

ToolWhy this one
kube-prometheus-stackPrometheus, Alertmanager and Grafana as one chart. What's portable is the rule format and query language, not the installer.
Alloy + LokiLog shipping and storage. Alloy ships from every pod, Loki stores, Grafana queries.
blackbox-exporterProbes each hostname from outside, so "is it up" is measured rather than assumed.
Trivy OperatorFindings as Kubernetes objects, so they query, alert and get triaged like everything else instead of sitting in a report nobody reads.
Falco + falcosidekickSyscall detection — what a process does after it starts, which admission and scanning structurally cannot see. Sidekick routes it through Alertmanager.

Acting

ToolWhy this one
HermesRead-only RBAC in the cluster, GitHub App identity in git. Its only write is a pull request, and the author is never the reviewer.
RedisOne job: the dedupe gate on alert-driven runs. A component this small is justified by the bill it prevents.
Actions Runner ControllerEphemeral runners that are pods in the cluster they test, so CI meets production's network rules.
RenovateOne PR per version bump, hourly, never merges. Understands Helm values and Kustomize overlays, which is most of this repo.
CrossplaneManages the GitHub webhook as an object, because the URL used to be a hand-copied secret nothing could rotate.
Discord + ntfyThe whole human interface. A channel per job, one webhook each, pushes for criticals only.

The hosts

ToolWhy this one
AnsibleNode config in the same repo, resolving secrets at run time. The OS is a machine problem and the cluster is a set of pinned versions; people ruin both by treating them as one.

Also present and unremarkable: metrics-server, an SMB CSI driver for the NAS, a registry mirror, and a container registry.

What I would do differently

  • The distribution was a lateral move. Off one Kubernetes distro and onto another — days of work, nothing bought.
  • Two things do one job between them. The cluster grew faster than the questions asked of it.
  • The agent can't be useful without a human. That's the design, not a dead end, but every fix waits for me.
The test I apply to any addition

If a component can't be justified by a question I've actually asked, it doesn't go in. Slow, and it's why the list is still short enough to read.
