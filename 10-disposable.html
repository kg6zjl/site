The pod is disposable, and so is everything in it

Config and skills are re-seeded from git on every start. Work happens in a fresh worktree per task, thrown away after. Nothing durable lives only inside the pod.

Designed to be killed without losing anything

The agent runs in a container designed to be killed without losing anything. Config and skills are re-seeded from git on every start. Work happens in a fresh worktree per task, thrown away after.

Nothing durable lives only inside the pod, which means "restart it" is always a safe first move.

Knowledge is versioned like code

The skills it loads per task are files in a repository it owns, with a history, and I can read any of them. When it learns something the hard way, the fix goes in the skill and gets committed — which is how most of the entries on Why got there.

Diagrams are code too

Every figure on this site is a Mermaid source file in the repository, rendered to SVG by a pinned image. Editing a diagram is editing text, reviewing it is reviewing a diff, and it cannot quietly drift from what the prose says — which is the failure mode of every diagram I have ever seen go stale.

The rule that came from breaking something

The agent may not change its own tooling without asking: its git configuration, its credential path, its deployment. It did once, mid-task, and then couldn't recover itself. Everything about its own environment needs me to approve it first, including when the change looks obviously correct.
